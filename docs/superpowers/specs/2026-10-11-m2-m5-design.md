# PromptCAD M2–M5 design

Oct 11, 2026 · design for milestones 2 to 5 of [`docs/SPEC.md`](../../SPEC.md), which stays the binding authority. This document records the decisions the spec leaves open, the order of work, and the **shared contracts** (names, types, files) that the four implementation plans must agree on. Each plan implements one milestone and may add detail, but must not rename or reshape anything in "Shared contracts".

Screens: [`design/screens/`](../../../design/screens/) (copied from https://claude.ai/artifact/TNXkMGKfbuVrEAh8MEvMDA, version `1791700959-9a31`). `Main`, `FirstRun`, `CompileError`, `Providers` belong to M2; `History`, `Gallery` and the Customizer dock in `Main` to M3; `Variants`, `Export`, `Phone*` to M4; `Refine`, `PhoneSketch` to M5.

## Decisions

| # | Decision | Source |
| --- | --- | --- |
| D1 | Providers tested end to end: DeepInfra, OpenRouter, OpenAI, Ollama, LM Studio, any OpenAI-compatible endpoint. Anthropic ships as one adapter among others, unit-tested against recorded SSE. Gemini is not built (the spec makes it optional). | User, brainstorm |
| D2 | Claude.ai subscriptions cannot power the app; Anthropic access is by API key only. | User, brainstorm |
| D3 | Storage is IndexedDB via Dexie from M2 on. M2 creates the database with `providerProfiles`, `usage`, `settings`; M3 adds the rest with a schema version bump. Keys are stored as plain strings in M2, masked in the UI; the optional passphrase lock is M3. | User, brainstorm |
| D4 | Layout follows the screens: desktop workbench `360px | 1fr | 440px` (Chat, 3D, Code); settings is a full page, not a dialog. Phone tabs are M4; until then narrow screens stack. | Screens |
| D5 | The OpenAI-compatible adapter uses `fetch` plus a small SSE parser. The Anthropic adapter uses the official `@anthropic-ai/sdk` with `dangerouslyAllowBrowser: true`. | Brainstorm |
| D6 | Chat history is in memory in M2 and persisted from M3 (`messages` table). In M2 "v1, v2…" chips are per-session turn numbers and "Back to vN" restores the code held in memory before that turn. M3 replaces both with real versions. | Brainstorm |
| D7 | **Customizer and statement parsing use a hand-written, comment- and string-aware OpenSCAD lexer** (`src/scad/`), not tree-sitter. OpenSCAD's own Customizer only reads top-level assignments, and click-to-refine only needs top-level statement ranges; both are bracket-depth problems a lexer solves. This avoids building and shipping a tree-sitter grammar WASM. The CodeMirror grammar stays hand-written. This answers the spec's open question and replaces the "tree-sitter-openscad" row of its tech stack table; the user is asked to confirm. | Assumption, flagged |
| D8 | BOSL2 and MCAD ship as optional per-project libraries (`projects.enabledLibraries`), downloaded by a pinned-URL + SHA-256 script like the OpenSCAD WASM, served from `public/libraries/`, written into the worker FS only when enabled. The system prompt mentions a library only when it is enabled. | Spec open question, assumption |
| D9 | 3MF export is not in v1. | Spec open question, assumption |
| D10 | Hosting: GitHub Pages at `/promptcad/` (already live). | CLAUDE.md |
| D11 | PWA icons: the design system has no logo and says never to draw a stand-in mark. The install icon is the wordmark's filament square (`brand-dot`) on `bg`, generated as PNG at build time from tokens. The user is asked to confirm. | Assumption, flagged |
| D12 | Click-to-refine (M5) starts with a spike that proves which OpenSCAD export format keeps per-face colour through Manifold CSG in the pinned WASM build (OFF with colours, then 3MF as fallback). The plan's later tasks are written for OFF and say exactly what changes if the spike picks 3MF. | Spec risk table |
| D13 | All IDs are `crypto.randomUUID()` strings. All timestamps are `Date.now()` numbers (ms). | Assumption |
| D14 | Money is US dollars as `number`; displayed with `formatCost` (below). Tokens are displayed with `formatTokens`. | Screens: "2,310 tok · $0.011" |

## Milestone scope

### M2 — AI loop

Exit: prompt to model without touching code, cost visible.

- Provider profiles page (**Settings › AI providers**, screen `Providers`): list, add, edit, delete; presets fill name, adapter and base URL:
  - OpenAI `https://api.openai.com/v1`
  - OpenRouter `https://openrouter.ai/api/v1`
  - DeepInfra `https://api.deepinfra.com/v1/openai`
  - Ollama `http://localhost:11434/v1`
  - LM Studio `http://localhost:1234/v1`
  - Anthropic `https://api.anthropic.com`
  - Custom (empty)
- **Test connection** reports CORS, auth and model errors in plain words, using the screen's callout (including the `OLLAMA_ORIGINS` hint for localhost). Capability switches (streaming, vision, audio) as on the screen; vision and audio are stored but unused until M4/M5.
- Model list from `GET /models` (cached in the profile, searchable), with a free-text fallback. Model picker (`pc-model`) in the composer; the choice is remembered in `settings.activeModel`.
- Chat column (screen `Main`): messages (`pc-msg`), meta line (turn chip, model, "1,180 tok · $0.006"), "$0.026 this chat" caption in the pane head, composer. The first-run callout and "Try asking for" suggestions (screen `FirstRun`) appear when there is no profile or the chat is empty.
- Edit protocol: first turn or empty editor → full file in one ```` ```openscad ```` fence; follow-ups → SEARCH/REPLACE blocks; if any block fails to apply, one automatic follow-up asks for the full file.
- Auto-fix loop: on compile failure, send the compiler errors back, up to `settings.autoFixAttempts` (default 2). UI per screen `CompileError`: error callout, "Auto-fix 1 of 2" busy pill, **Stop auto-fix**, **Back to vN**.
- Token and cost tracking: provider-reported cost when present (`usage.cost` from OpenRouter), else the profile's editable per-model price table, else tokens only ("price unknown"). Every response writes a `usage` row. The providers page shows "This month" per profile (screen `Providers`). The settings nav shows "Usage and cost", but that section is M3.
- Header gains the **Settings** button (gear) and the view switch to the settings page.
- Out of M2: everything in M3–M5, Gemini, passphrase lock.

### M3 — Parametric and history

Exit: start from a gallery model, tune sliders, restore any version.

- Dexie schema v2: `projects`, `versions`, `messages`, `presets`, `blobs`, `printerProfiles` (reserved, empty), and the new `settings` fields.
- Projects: header project button (`project`) opens a menu: new, rename, open recent, delete, export `.json`, import `.json` (schema-validated). Last open project restores on load. `navigator.storage.persist()` requested on first project.
- Versions per spec "Projects and version history": created on AI turn (`ai`), auto-fix (`autofix`), slider bake and slider change commit (`slider`), manual edit coalesced (render success, blur, or 30 s idle → `manual`), restore (`restore`), gallery start (`gallery`), link import (`import`). Each has a 96 px PNG thumbnail captured from the viewer canvas.
- History view (screen `History`): version list with source icons, branch indentation, failed state, "+ N variants not picked", Compare (side-by-side diff with `+N −N`), Preview pane with a live mini viewer, **Restore vN**, **Branch from here**. Undo/redo (Ctrl+Z/Ctrl+Shift+Z outside the editor, and header buttons) move the head along its ancestry.
- Chat persistence: M2's chat messages become `messages` rows tied to their version; turn chips show version labels.
- Customizer (screen `Main` dock): parser in `src/scad/customizer.ts` (D7), controls per spec table (slider + number, number with step, dropdown, toggle, text, vector), tabs from `/* [Group] */`, "changed" marker, **Reset**, **Bake into code**, named presets per project. Changes re-render via `-D` without touching source. Un-annotated top-level numbers get a number input and an **Ask AI to annotate** button.
- Gallery (screen `Gallery`): 8 bundled parametric examples as `src/gallery/examples/*.scad` plus `index.ts` metadata (name, tags, category, glyph). "Start from this" creates a project with version 1. Thumbnails are the iso line glyphs from the screen, not renders.
- Settings sections: **Usage and cost** (per profile per day and month), **Rendering** (debounce, timeout, auto-fix attempts), **Libraries** (D8), **Appearance** (theme: system/dark/light), **Storage and backup** (usage estimate, persist status, export all), **Security** (passphrase lock: PBKDF2 → AES-GCM via WebCrypto, key held in memory until the tab closes).
- Problems tab next to `main.scad` (screen `CompileError`), OpenSCAD version in the console head.

### M4 — Variants, sharing, PWA

Exit: install on phone, dictate a prompt, pick a variant, share a link.

- `RenderQueue` (second worker, FIFO, same timeout) for renders that must not disturb the main view: variants, timelapse frames.
- Variants (screen `Variants`): variant count button in the composer (1 or 3; `settings.variantCount`); 3 parallel requests (same model, or the profile's chosen models); queued renders; 3-up picker with orbitable previews, status, dims, params count, cost; **Use variant X**, **Regenerate**, **Discard all**; unpicked ones stored as `kind: 'variant'` versions sharing a `variantGroupId`.
- Export dialog (screen `Export`), opened by a new header **Share** button; **Export STL** stays a one-click primary button, as on the screens. Tabs: **Model file** (STL, `.scad`), **Image** (PNG: size, transparent/solid, camera preset), **Turntable** (GIF via `gifenc` in a worker; frame count 36–72; size; background), **Timelapse** (spec "Timelapse GIF"), **Link**. One offscreen frame renderer feeds all image tabs.
- URL share: `#s=` + lz-string of `{ v: 1, name, code, params }`; over 8 KB warns and offers a `.json` file. Opening a link imports a new project (`origin: 'shared-link'`). No keys, chat or history.
- PWA: `vite-plugin-pwa` (Workbox) precaches the app shell, OpenSCAD WASM and library zips; "New version available" prompt; manifest with D11 icons, `display: standalone`; download progress "Loading OpenSCAD 5.2 / 8.4 MB" in the status pill and console.
- Phone layout (screens `PhoneChat`, `Phone3D`, `PhoneCode`): `pc-tabbar` Chat/Code/3D under `md`, symbol key row above the keyboard in Code, parameter bottom sheet in 3D, 44 px viewer buttons.
- Voice prompts: Web Speech API dictation into the composer with the screen's caption; MediaRecorder + `/audio/transcriptions` fallback when the profile has `audio`; otherwise the mic button is hidden.
- Mobile performance: optional low-`$fn` preview pass, triangle warning over ~1M, pixel ratio cap 2, pause the render loop when the 3D tab is hidden.

### M5 — Vision and click-to-refine

Exit: tap a part and change only it.

- Spike (D12): colour survival through CSG in the pinned build; choose preview format.
- Image and sketch input: attach button (file picker, paste, drop), sketch canvas with dimension annotations (screen `PhoneSketch`), downscale to max 1568 px long edge, store as `blobs` (`kind: 'image'`) linked from `messages.imageBlobIds`. Disabled with an explanation when the profile lacks `vision`.
- Adapters send image parts (OpenAI `image_url` data URLs; Anthropic `image` base64 blocks). The types for this exist from M2 (see `ContentPart`).
- Tag-colour instrumentation: `src/scad/statements.ts` lists top-level statements and module calls in the main assembly with source ranges; `src/scad/tagging.ts` wraps each in `color([r,g,b])` encoding a tag id; the preview render uses the tagged code and the colour-preserving format; the worker returns `faceTags`.
- Picking: ray hit → face index → tag → source range; highlight in 3D (`pick` token) and in the editor (`cl.is-pick` equivalent decoration); popover per screen `Refine` (**Ask AI**, **Show code**); "Tap empty space to clear · Esc".
- Scoped edits: the composer shows the pick chip "bores · lines 15–17 — Only this part will change"; the prompt carries the range; SEARCH blocks outside the range are rejected and retried once.
- Fallbacks: if tags are lost (e.g. inside `hull()`), select by bounding box and send a viewport screenshot with the selection outlined to a vision model.
- Optional visual check after a successful render (setting, off by default): screenshot to a vision model asking whether it matches the request.
- Final STL export always renders the untagged code, so the user's own `color()` calls are untouched.

### Edit protocol (`src/ai/edits.ts`, M2)

```ts
export interface SearchReplace { search: string; replace: string }
export type ParsedReply =
  | { kind: 'full'; code: string; prose: string }
  | { kind: 'edits'; edits: SearchReplace[]; prose: string }
  | { kind: 'none'; prose: string }
export function parseReply(text: string): ParsedReply
export type ApplyResult = { ok: true; code: string } | { ok: false; failedIndex: number }
/** Each search must match exactly once (after normalising CRLF); edits apply in order. */
export function applyEdits(code: string, edits: SearchReplace[]): ApplyResult
```

Block format (outside any code fence):

```
<<<<<<< SEARCH
exact lines from the current file
=======
replacement lines
>>>>>>> REPLACE
```

`prose` is the reply with fences and blocks removed, trimmed; it is what the chat bubble shows.

### Turn orchestration (`src/ai/runTurn.ts`, M2)

Split into two composable steps so M4 variants can reuse the generation without touching the editor:

```ts
export interface GenerateResult {
  code: string | null               // null when the reply had no usable code
  prose: string
  usage: Usage
  model: string
}
/** Streams one reply, applies it to baseCode (full file or edits, with one full-file retry when an edit fails). */
export function generateCode(opts: {
  provider: LlmProvider
  model: string
  history: LlmMessage[]
  userText: string | ContentPart[]
  ctx: PromptContext
  signal: AbortSignal
  onDelta?(text: string): void
  temperature?: number
}): Promise<GenerateResult>

export type TurnEvent =
  | { type: 'delta'; text: string }
  | { type: 'reply'; result: GenerateResult; attempt: number }   // attempt 0 = first reply, 1..N = auto-fix
  | { type: 'rendered'; result: RenderResult; attempt: number }
  | { type: 'fixing'; attempt: number; of: number; errors: string }
  | { type: 'gave-up'; attempts: number }

/** generateCode → render → on failure send the errors back, up to maxFixAttempts. */
export function runTurn(opts: {
  provider: LlmProvider
  model: string
  history: LlmMessage[]
  userText: string | ContentPart[]
  ctx: PromptContext
  maxFixAttempts: number
  render(code: string, signal: AbortSignal): Promise<RenderResult>
  apply(code: string, source: 'ai' | 'autofix'): void
  onEvent(e: TurnEvent): void
  signal: AbortSignal
}): Promise<void>
```

## Cross-cutting rules (all plans)

Copied into every plan's Global Constraints: CLAUDE.md "Rules that are easy to break" (TDD, tokens only, design-system voice, strict CSP, untrusted model output as text only, pinned WASM, base path), the M1 plan's design-system constraints, and the git workflow (one logical change per commit, conventional messages, `npm run typecheck && npm test && npm run e2e` green before every push).

New dependencies are allowed only as named in the plan that introduces them: M2 `dexie`, `fake-indexeddb` (dev), `@anthropic-ai/sdk`; M3 `diff`; M4 `lz-string`, `gifenc`, `vite-plugin-pwa`; M5 none expected (3MF fallback would move `fflate` to dependencies).

## Contract amendments from planning

The four plans were written in parallel against the contracts above. Each listed where a contract fell short; these resolutions are binding for execution and override the sections above where they differ.

- **Names fixed by the M2 plan** and used by M3–M5: `useChatStore` (`messages`, `addMessage`), `sendPrompt(text, deps)`, `stopTurn`, `goBack`; `useProvidersStore`; `Composer` and `ChatPanel` in `src/chat/`; repositories `listProfiles`, `saveProfile(profile): Promise<ProviderProfile>`, `deleteProfile`, `newProfile`, `getSettings` (fills missing fields from `DEFAULT_SETTINGS`), `updateSettings(patch)`, `addUsage`. M4's `src/variants/recordUsage.ts` must wrap `addUsage`, not write the table itself.
- **Manual edits during a turn.** `awaitRender` does not settle when the code changes before the render lands; every caller aborts its turn when the user edits the code (M2) or moves a slider (M3).
- **Variant diversity.** The Anthropic adapter never sends `temperature`. Variants therefore also vary the instruction per slot (B: "a different approach from the obvious one", C: "the simplest printable design"), so Anthropic profiles still get three distinct results; temperature stays an extra lever for adapters that accept it.
- **Settings fields** added beyond the list above: `lockSalt`, `lockVerifier` (M3), `transcriptionModel` (M4). `visualCheck` (M5) needs no schema bump; readers default it to false.
- **Store fields** added beyond the list above: `renderedParams`, `libraries`/`setLibraries` (M3). AI and auto-fix code changes clear `params`.
- **Version labels.** `createVersion` resolves label clashes from `nextLabel`. A blank project's v1 uses source `'manual'`. M3 replaces M2's per-session `turnLabel` with the version label.
- **Head moves.** M4 adds `setHead(versionId)` to move the head to an existing version without creating one.
- **Click-to-refine scope (M5).** Tags are applied only to top-level statements and main-assembly children, because an outer `color()` overrides inner ones; picking inside a module body (the Refine screen's "bores") is deferred beyond v1. The spike against the pinned WASM chose OFF as the tagged preview format.
- **`RenderController.onStart`** gains an optional `req` argument (backward compatible), so a quiet tagged follow-up render does not flip the status pill.
